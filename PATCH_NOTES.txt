DOWNLOAD BUTTON CRASH FIX — YTMusicUltimate on YouTube Music 9.23.4
====================================================================

ROOT CAUSE (proven by binary analysis):
----------------------------------------
YTPlayerViewController.playerResponse was REMOVED in YouTube Music 9.17.2.
The tweak's Downloading.x called this selector at 3 call sites, causing:

  NSInvalidArgumentException: -[... playerResponse]: unrecognized selector sent to instance

Tool: custom Mach-O/dyld4 parser (ktool + handwritten Python)

  - contentVideoID              ← still present
  - currentVideoTotalMediaTime  ← still present

YTPlayerResponse methods (36 total, relevant):
  - playerData                  ← still present

YTIPlayerResponse (protobuf-generated, confirmed via methname section):

  - hlsManifestURL              ← still present

  - thumbnailsArray             ← still present

SELECTOR MAPPING (OLD → NEW):
------------------------------
  playerVC.playerResponse  →  playerVC.contentPlayerResponse
  (all other chained calls are unchanged: .playerData, .videoDetails, .streamingData,
   .streamingData.hlsManifestURL, .videoDetails.thumbnail.thumbnailsArray)

SOURCE CHANGES:
---------------
  Source/Headers/YTPlayerViewController.h:
    - @property playerResponse → @property contentPlayerResponse

  Source/Downloading.x:
    - All 3 call sites: playerVC.playerResponse → playerVC.contentPlayerResponse
    - downloadCoverImage: [UIApplication sharedApplication].keyWindow replaced with
      connectedScenes-based lookup (iOS 13+ multi-scene safe, with keyWindow fallback)

     (in __TEXT.__const section, previously-zero padding; 4102-byte null run available)
  
  2. Updated __objc_selrefs[287] at file offset 0xfff768:
     OLD: 0xc5c17b (→ "playerResponse" in __objc_methname)

KEYWINDOW:
----------
  [UIApplication sharedApplication].keyWindow is deprecated in iOS 15+ but does NOT
  crash — nil message sends in ObjC are NOPs. Source updated to use connectedScenes
  for a proper multi-scene-safe lookup. The existing binary still uses keyWindow
  (non-crashing in foreground use; proper fix requires rebuild with Theos/iOS SDK).
